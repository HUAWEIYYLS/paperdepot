# 论文库摘要 Skill（给插件宿主里的 LLM 用）

> 这个文件是论文库插件的**摘要提示词契约**：插件在导入后把「本 skill + 本次任务 + 受控词表 + digest 材料」拼成一次请求。
> 它同时适合人工审阅：写出来的摘要应该能直接放进 Obsidian，被 Claudian 检索、被你自己快速读懂。

## 目标

把一篇论文的 digest 变成两样东西，**写进同一个条目目录**：

1. `summary.md`：结构化中文摘要（一句话总结 + 背景 + 方法 + 结果 + 结论 + 数据表 + 结构）
2. `tags.md`：四类受控标签（研究领域 / 技术方法 / 应用场景 / 仪器设备）

产出的摘要要满足两个用途：

- **给人读**：同行读完能判断"这篇跟我有没有关系"
- **给检索用**：标题、术语、数字、标签都能被 Obsidian 搜索 / Claudian 的文件检索命中

## 输出契约（硬性）

只输出**一个 JSON 对象**，不要 Markdown 代码围栏，不要解释文字：

```json
{"summary_md": "...", "tags_md": "...", "aliases": ["..."], "keywords": ["..."], "citekey": "..."}
```

- `summary_md` 以 `# 📖 论文摘要` 开头
- `tags_md` 以 `# <论文标题> - 标签` 开头
- `aliases`：2–6 个中英文别名（概念/项目/仪器/方法名，供检索用）；没有就给 `[]`
- `keywords`：5–10 个检索关键词（中文术语优先）；没有就给 `[]`
- `citekey`：小写、无空格，`第一作者姓+年份+关键词`（如 `sun2023rapidfrd`）；拿不到作者就给 `""`

## summary.md 结构（小节标题必须逐字保留）

```markdown
# 📖 论文摘要

## 一句话总结

> 一句话：做了什么 + 关键方法 + 最关键的数字结果。

## 研究背景

- **问题重要性**：...
- **技术难点**：...

## 研究方法

### 核心思路

> 用通俗的话解释这篇论文做了什么、怎么做的。

### 原理详解

- **核心原理**：...
- **数学/算法逻辑**：...
- **与已有方法的关系**：...

### 关键步骤

1. **步骤名** — 做什么 + 为什么
2. ...

## 主要结果

| 指标 | 结果 |
|------|------|
| ... | ... |

## 结论与贡献

1. **贡献项** — 描述
2. ...

## 📊 关键数据汇总

| 参数 | 值 |
|------|----|
| ... | ... |

## 📈 论文结构

1. 章节名 — 一句话说明
2. ...
```

## 检索友好要求（重要）

这些要求是为了让 **Claudian / Obsidian 搜索**能快速找到这篇论文：

1. **一句话总结**控制在 40–120 字，必须包含：核心方法名 + 关键结果数字（若有）；不要只写"本文研究了…"。
2. 专业术语**中英并列**首次出现时写全，例如「焦比退化（focal ratio degradation, FRD）」「准近场模型（quasi-near field model）」。这样中英文查询都能命中。
3. **关键数字**（精度、误差、样本量、波段、年份范围）同时出现在「一句话总结」或「主要结果」里，且必须能在 digest / full.md 找到原值。
4. 不要用"该文""作者认为"这类空话开头；直接写对象、方法、结果。
5. 每个小节保持独立可读，不要写"如上所述"依赖上下文。
6. 仪器 / 项目名（LAMOST、DESI、MUSE、FASOT-IFU 等）原样保留英文缩写。

## tags.md 规则

- 四个小节固定为：`## 研究领域`、`## 技术方法`、`## 应用场景`、`## 仪器设备`
- **每类 2–5 个标签**
- **只能从请求末尾附带的「受控标签词表」里逐字选择**：禁止自造、禁止改字、禁止只写英文
- 同义/缩写以词表里的写法为准（例如词表写「焦比退化」就不要写「FRD」）
- 确实需要新词时，宁可不加，也不要造词（后续由人补词表）

## 质量红线

- ❌ 不编造数据、作者、期刊、结论
- ❌ 不把"论文说了"写成"我认为"
- ✅ 所有数字必须能在材料里找到；找不到就写定性结论
- ✅ 全文中文，专业术语保留英文原名
- ✅ 公式用 LaTeX：`$$...$$` 或 `$...$`
- ✅ 方法部分面向同行但不熟悉该方向的人，讲人话

## 自检（插件会跑 `tools/validate_summary.py`）

提交前在脑内过一遍：

- [ ] 小节标题齐全、拼写正确
- [ ] 一句话总结有方法 + 数字（若有）
- [ ] 标签每类 ≥2，且全部来自词表
- [ ] 摘要里出现的每个数字，都能在材料里找到
- [ ] 没有编造的作者/期刊/年份
