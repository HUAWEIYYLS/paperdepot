# 概念层规范（2-Concepts）

> 目标：为**跨论文概念**建页面，让论文库从"一堆条目"变成"一张知识网"。

---

## 一、定位（决策 4 的落地）

`1-Papers/` 装论文，`2-Concepts/` **只装概念**——一个概念横跨多篇论文时才建页。
单篇论文独有的技术细节留在该论文的 `index.md`，不放概念层。

```
<vault>/2-Concepts/<概念名>.md      ← 一页一个概念，扁平，不建子目录
```

为什么扁平：

| 约束 | 原因 |
|---|---|
| 一个概念 = 一个 `.md` 文件 | 概念页无图无 PDF，不需要 `index.md` 那套目录结构 |
| 文件名 = 概念名 | 双链 `[[概念名]]` 最短、手机端可点、Graph 视图里名字可读 |
| 不用插件 | 纯 frontmatter + wikilink，Obsidian 原生 Properties / Backlinks / Graph / 标签面板全部直接可用 |

## 二、frontmatter schema

```yaml
---
title: "焦比退化"                 # 概念中文名（与文件名一致）
type: concept                    # 固定值，供 Dataview / Properties 区分论文与概念
aliases:                         # 别名：英文、缩写、常见异写，方便搜索与双链
  - "FRD"
  - "Focal Ratio Degradation"
tags:                            # 只允许用受控词表里的规范词（见 config/tagmap_*.json）
  - "领域/天文光纤光谱处理"
  - "方法/焦比退化"
  - "仪器/光纤光谱仪"
papers: 26                       # 本页实际引用的论文数
updated: 2026-10-27
---
```

- `tags` 沿用论文的四类分层标签体系，**不新增"概念/..."类别**——这样点标签能同时看到论文和概念。
- `papers` 是引用计数，用于排序和人工抽查。

## 三、页面结构（固定章节名）

```markdown
# 概念名

> **一句话**：≤80 字，说清"是什么 + 为什么在天文仪器里要紧"。

## 定义与物理图像     概念是什么、怎么度量、典型量级、为什么发生
## 工程后果           它如何影响仪器设计 / 巡天效率 / 测量精度
## 测量与评价方法      怎么测、怎么量化，按方法演进讲
## 各文献的贡献        表格：论文 | 年份 | 做法 | 关键结论（数字）
## 共识与分歧          哪些结论一致、哪些互相矛盾，各自出处
## 相关概念            纯文本列概念名（试点阶段不建链，避免断链）
## 📄 相关论文         按年份排序的 wikilink 列表
```

`各文献的贡献` 分两张表：

- **核心文献** — 直接研究 / 测量 / 建模该概念的论文
- **相关文献** — 仪器论文或处理流水线中顺带报告该指标、把它当设计约束的论文

## 四、链接规范

- 论文笔记一律是 `1-Papers/<目录>/index.md`，所以：

  ```markdown
  [[1-Papers/<目录>/index|短标题]]
  ```

  目录名**逐字**取自素材的「目录：」行，不要手打。
- 目录名含 `[` `]` `^` 等 wikilink 特殊字符时（目前 2 个：`Astrophotonics… [Invited]`、
  `Point-spread function reconstruction… l^1-l^p model`），**不建链**，用纯文本标题列出，
  避免断链；后续若重命名目录再去掉这个例外。

- **只链接确实存在的条目**。`## 相关概念` 里，目标概念页已存在的用 wikilink
  `[[2-Concepts/<概念名>|<概念名>]]`，还不存在的用纯文本列名（避免断链）。

## 五、写作规则（硬约束）

1. **数字必须可溯源**：页面里出现的每个数字，必须能在对应论文的 `index.md` 里找到；不推算、不四舍五入出原文没有的数。
2. **只写你能从素材里读到的**：不补充外部知识里的具体数值；不确定就写定性结论。
3. **区分"核心"与"相关"**：不要把仪器论文里一句"FRD 损失约 10%"抬成核心结论。
4. **共识与分歧必须指名出处**（哪年、哪篇），这是概念页相对论文摘要的唯一增量。
5. 中文技术写作，不用"本文将……"的作业腔，不写空话。

## 六、生成与校验流程

```
候选概念（人工定义，≥3 篇论文）
  ↓ 素材抽取：按标签机械召回 + 人工按标题/摘要筛相关
cache/_concept_<概念>.md（每篇：目录/年份/一句话总结/主要结果）
  ↓ LLM 撰写（每页一个 agent，可并行）
2-Concepts/<概念名>.md
  ↓ 程序校验
  ① YAML 可解析、schema 字段齐全
  ② wikilink 全部命中 1-Papers/<目录>/index.md
  ③ 数字溯源：页面数字 ⊆ 素材数字
  ④ tags ⊆ 受控词表
  ↓ 人工抽查 1–2 页
```

校验脚本做成 `tools/verify_concepts.py`，全量铺开时按批次跑。

## 七、验收标准

- 每页 `papers` ≥ 5（不足 5 篇的合并或放弃）
- 断链 0
- 数字溯源失败 0（或人工确认的例外清单）
- 首页 `2-Concepts/_index.md` 可浏览全部概念
